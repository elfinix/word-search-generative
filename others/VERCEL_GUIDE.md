# 🚀 Vercel Deployment Guide for PokéSearch

This guide details how to publish your **PokéSearch Generative Web Application** to **Vercel** with the **FastAPI** backend serverless API, **Google Gemma 4 31B LLM**, and **Supabase** database integration.

---

## 🛠️ Step 1: Vercel Project Architecture Setup

Vercel can deploy both the React Vite frontend and the FastAPI Python backend as a single monorepo using Vercel Serverless Functions.

Create a `vercel.json` file in the root directory:

### Create `vercel.json`
```json
{
  "version": 2,
  "builds": [
    {
      "src": "backend/app/main.py",
      "use": "@vercel/python"
    },
    {
      "src": "frontend/package.json",
      "use": "@vercel/static-build",
      "config": {
        "distDir": "dist"
      }
    }
  ],
  "routes": [
    {
      "src": "/api/(.*)",
      "dest": "backend/app/main.py"
    },
    {
      "src": "/(.*)",
      "dest": "frontend/$1"
    }
  ]
}
```

## 🔑 Step 2: Configure Environment Variables on Vercel

In your Vercel Dashboard under **Project Settings ➔ Environment Variables**, add the following key-value pairs:

| Key | Example Value | Purpose |
| :--- | :--- | :--- |
| `GEMINI_API_KEY` | `<YOUR_API_KEY_HERE>` | Google Gemini / Gemma API Key |
| `GEMINI_MODEL` | `models/gemini-3.5-flash-lite` | The active LLM model ID |
| `GEMINI_API_VERSION` | `v1beta` | Gemini API Version |
| `SUPABASE_URL` | `https://iudaicigclucruffjfqk.supabase.co` | Supabase Database Project Endpoint |
| `SUPABASE_SERVICE_ROLE_KEY` | `<YOUR_SUPABASE_SERVICE_ROLE_KEY>` | Supabase Service Role Key (Required to bypass RLS) |

## 🗄️ Step 3: Initialize Supabase SQL Database Table

Log in to your **Supabase Dashboard** (`https://supabase.com`) ➔ **SQL Editor**, and run the following DDL script to create the `scores` leaderboard table in the `public` schema:

```sql
-- Create scores table for PokéSearch
create table if not exists public.scores (
    id bigint generated by default as identity primary key,
    player_name text default 'Trainer',
    difficulty text not null,
    time_seconds integer not null,
    score integer not null,
    created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Create game_stats table
create table if not exists public.game_stats (
    id bigint generated by default as identity primary key,
    puzzles_completed integer default 0 not null,
    words_found integer default 0 not null,
    created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Insert initial stats row if it doesn't exist
insert into public.game_stats (id, puzzles_completed, words_found)
values (1, 0, 0)
on conflict (id) do nothing;

-- Enable Row Level Security (RLS)
-- By enabling this without policies, we BLOCK all public anon access.
-- The backend uses the SUPABASE_SERVICE_ROLE_KEY to bypass this securely.
alter table public.scores enable row level security;
alter table public.game_stats enable row level security;
```

## 🚀 Step 4: Publish to Vercel via CLI or GitHub

### Option A: Deploy via Vercel CLI

1. Install Vercel CLI globally:
   ```bash
   npm install -g vercel
   ```

2. Log in and deploy from project root:
   ```bash
   vercel login
   vercel
   ```

3. Deploy to production:
   ```bash
   vercel --prod
   ```

### Option B: Deploy via GitHub Integration

1. Push your code to a GitHub repository:
   ```bash
   git add .
   git commit -m "Add Vercel configuration, PokeAPI, Gemma LLM, and Supabase integration"
   git push origin main
   ```

2. Open [Vercel Dashboard](https://vercel.com/new), select **Import Project**, choose your repository, and paste the environment variables from **Step 2**.

3. Click **Deploy**.
